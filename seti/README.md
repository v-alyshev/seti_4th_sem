# lan_copies — обнаружение копий приложения в локальной сети

Приложение находит свои копии, запущенные в локальной сети, с помощью обмена multicast UDP-сообщениями. Оно отслеживает появление и исчезновение копий и при каждом изменении выводит список IP-адресов «живых» копий.

Адрес multicast-группы передаётся параметром. Протокол (IPv4 или IPv6) выбирается автоматически по этому адресу.

## Возможности

- Работа в IPv4 и IPv6 сетях с автоматическим выбором протокола по адресу группы.
- Обнаружение появления копий и их исчезновения:
  - при штатном завершении (Ctrl+C, `SIGTERM`) копия отправляет сообщение `BYE` и сразу удаляется из списков;
  - при аварийном завершении (`kill -9`, обрыв сети) копия удаляется по таймауту, если от неё 5 секунд не было сообщений.
- Различение нескольких копий на одном компьютере: у них общий IP, но разные идентификаторы.
- Вывод списка только при изменении состава копий.
- Необязательный выбор сетевого интерфейса. Если интерфейс не указан, программа сама выбирает первый подходящий: поднятый, с поддержкой multicast, не loopback, с адресом нужного протокола.
- Отслеживание потерь пакетов: каждое `HELLO` содержит порядковый номер, и для каждой обнаруженной копии считается, сколько её сообщений получено, потеряно, пришло с опозданием и повторно. Повторы и сообщения, пришедшие не по порядку, не увеличивают счётчик потерь.
- Трафик ограничен локальным сегментом (TTL / Hop Limit = 1).

## Требования

- Linux;
- компилятор с поддержкой C++17 (GCC 7+ или Clang 5+);
- CMake 3.10+.

```bash
sudo apt install build-essential cmake
```

## Сборка

```bash
cmake -B build
cmake --build build
```

Исполняемый файл: `build/lan_copies`.

## Запуск

```
lan_copies <адрес multicast-группы> [порт] [интерфейс]
```

| Параметр | Обязательный | По умолчанию | Описание |
|---|---|---|---|
| адрес группы | да | — | IPv4 (`224.0.0.0/4`) или IPv6 (`ff00::/8`) multicast-адрес |
| порт | нет | `30000` | UDP-порт, 1–65535 |
| интерфейс | нет | выбирается автоматически | имя сетевого интерфейса, например `enp0s3` |

Для IPv6 интерфейс можно указать и через зону в адресе: `ff02::4321%enp0s3`.

### Примеры

```bash
# IPv4
./build/lan_copies 239.192.0.1
./build/lan_copies 239.192.0.1 40000
./build/lan_copies 239.192.0.1 30000 enp0s3

# IPv6
./build/lan_copies ff02::4321%enp0s3
./build/lan_copies ff02::4321 30000 enp0s3
```

Если интерфейс не указан и подходящих несколько, программа выберет первый и выведет предупреждение со списком. Если подходящих нет, она завершится с ошибкой.

Выход — Ctrl+C.

## Протокол

Сообщения передаются UDP-датаграммами на адрес группы, в текстовом виде:

```
LAN_COPIES_V2 <тип> <id> <номер>
```

| Поле | Значение |
|---|---|
| `LAN_COPIES_V2` | метка протокола и его версия; отсекает посторонние пакеты |
| тип | `HELLO` — «я работаю», `BYE` — «я завершаюсь» |
| id | случайный 64-битный идентификатор копии, 16 hex-символов |
| номер | порядковый номер `HELLO`, десятичное число от 0; увеличивается на 1 после каждой успешной отправки |

- Каждая копия отправляет `HELLO` раз в **1 секунду**.
- Копия считается исчезнувшей, если от неё нет сообщений дольше **5 секунд**.
- При штатном завершении копия отправляет `BYE`.
- Сообщения, не совпадающие с форматом в точности (лишние поля, пробелы, неверный ID), отбрасываются.
- Свои собственные сообщения копия распознаёт по ID и игнорирует.

## Отслеживание потерь пакетов

Каждое `HELLO` содержит порядковый номер. Копия-отправитель начинает с 0 и увеличивает номер на 1 после каждой успешной отправки. Если отправка не удалась, следующая попытка уйдёт с тем же номером, поэтому сбой отправки не выглядит у получателей как потеря в сети.

Получатель ведёт учёт номеров отдельно для каждой обнаруженной копии (класс `SequenceTracker`). По пропускам в нумерации он определяет, сколько сообщений этой копии не дошло.

### Как определяется потеря

Для каждой копии хранятся:

- первый полученный номер;
- наибольший полученный номер;
- количество полученных сообщений;
- 64-битная маска: какие из последних 64 номеров (считая от наибольшего) уже пришли.

| Пришёл номер | Событие | Что происходит |
|---|---|---|
| первый от этой копии | — | начинается отсчёт |
| следующий за наибольшим | — | сообщение учтено |
| больше ожидаемого | **пропуск** | номера между ними считаются потерянными |
| меньше наибольшего, ещё не приходил | **опоздание** | сообщение учитывается, потеря отменяется |
| уже приходил | **повтор** | сообщение отбрасывается |
| старше 64 последних | **повтор** | отбрасывается: проверить его уже нельзя |

Число потерь не хранится отдельно, а вычисляется:

```
ожидалось = наибольший номер − первый номер + 1
потеряно  = ожидалось − получено
```

Поэтому:

- **повтор не увеличивает потери**: он не учитывается как полученный и не меняет диапазон ожидаемых номеров;
- **опоздавшее сообщение уменьшает потери**: сначала его номер был учтён как пропущенный, а когда оно пришло, «получено» выросло на 1.

Маска нужна только для того, чтобы отличить опоздавшее сообщение от повтора. Бит равен 1, если сообщение с этим номером уже пришло. При получении нового наибольшего номера маска сдвигается, чтобы её биты по-прежнему соответствовали своим номерам.

### Вывод статистики

Статистика по копии выводится в виде:

```
Получено 17 из 18, потеряно 1 (5.6%), с опозданием 0, повторов 0.
```

| Поле | Значение |
|---|---|
| получено | сколько разных сообщений дошло |
| из | сколько должно было дойти: от первого полученного номера до наибольшего |
| потеряно | разница, в скобках — доля от ожидаемого |
| с опозданием | сколько сообщений пришло не по порядку |
| повторов | сколько дубликатов отброшено |

Когда выводится:

- **сразу при событии** — пропуске, опоздании или повторе:
  ```
  [18:40:14] 192.168.56.12 (id 0f2f4d95b7165ba7): пропущено сообщений: 1 (пришло #11). Получено 11 из 12, потеряно 1 (8.3%), с опозданием 0, повторов 0.
  [18:40:15] 192.168.56.12 (id 0f2f4d95b7165ba7): сообщение #10 пришло с опозданием, потеря отменена. Получено 12 из 12, потеряно 0 (0.0%), с опозданием 1, повторов 0.
  [18:40:16] 192.168.56.12 (id 0f2f4d95b7165ba7): повтор сообщения #11, пропущен. Получено 12 из 12, потеряно 0 (0.0%), с опозданием 1, повторов 1.
  ```
- **каждые 10 секунд** — «Статистика потерь» по всем живым копиям;
- **при уходе копии** (по `BYE` или по таймауту) — её итоговая статистика;
- **при выходе из программы** — «Итоговая статистика» по копиям, которые ещё живы.

### Ограничения

- Если копия пропала по таймауту, а потом снова появилась с тем же ID, её статистика начинается заново.
- Перезапущенная копия получает новый ID и считается новой копией.
- Сообщение, опоздавшее больше чем на 64 номера (больше минуты при отправке раз в секунду), отбрасывается как повтор, и его потеря не отменяется.

## Структура проекта

| Файл | Содержимое |
|---|---|
| `main.cpp` | точка входа, обработка ошибок верхнего уровня |
| `app.h/.cpp` | разбор аргументов, обработка сигналов, главный цикл |
| `multicast_socket.h/.cpp` | multicast UDP-сокет для IPv4/IPv6: разбор адреса группы, вступление в группу, отправка и приём |
| `protocol.h/.cpp` | формат сообщений, сборка и разбор, генерация ID, интервал и таймаут |
| `peer_table.h/.cpp` | таблица живых копий, удаление по таймауту, вывод списка и статистики |
| `sequence_tracker.h/.cpp` | учёт порядковых номеров одной копии: потери, опоздания, повторы |
| `announcer.h/.cpp` | отправка `HELLO` и `BYE` |
| `listener.h/.cpp` | приём и обработка входящих сообщений |
| `common.h/.cpp` | общие вспомогательные функции |
| `CMakeLists.txt` | сборка |

## Проверка

**1. Появление.** Запустить программу с одной и той же группой на нескольких машинах. Каждая копия выведет список остальных.

**2. Штатное исчезновение.** Нажать Ctrl+C на одной из копий. У остальных она сразу пропадёт из списка.

**3. Аварийное исчезновение.** Запустить копию в фоне и убить её без отправки `BYE`:

```bash
./build/lan_copies 239.192.0.1 &
kill -9 %1
```

У остальных копий она пропадёт примерно через 5 секунд.

**4. Несколько копий на одной машине.** Запустить программу в двух терминалах одного компьютера. В списке будут одинаковые IP с разными ID.

**5. Разные группы.** Копии, запущенные с разными адресами групп, друг друга не видят.

**6. Потери.** Запустить копии на двух машинах и на одной из них имитировать плохую сеть. У другой копии появятся сообщения о пропусках, а в статистике вырастут потери. Способы:

- Случайные потери средствами Linux:

  ```bash
  sudo tc qdisc add dev enp0s3 root netem loss 30%     # включить
  sudo tc qdisc del dev enp0s3 root                    # выключить
  ```

- Кратковременный обрыв: в VirtualBox снять галочку «Подключить кабель» у одной машины на 2–3 секунды (меньше таймаута в 5 секунд).

- Частая отправка: в `protocol.h` уменьшить интервал, например `kSendInterval = std::chrono::milliseconds(1)`, и пересобрать. При тысячах сообщений в секунду потери возникают сами. После проверки вернуть `std::chrono::seconds(1)`.

**7. Ошибки параметров.**

```bash
./build/lan_copies                          # справка
./build/lan_copies 192.168.1.1              # не multicast-адрес
./build/lan_copies 239.192.0.1 99999        # неверный порт
./build/lan_copies 239.192.0.1 30000 nosuch # нет такого интерфейса
```
